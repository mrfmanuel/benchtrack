# Release check

Run every step, from the repo root, and **report each result with its real output** (counts, exit codes). Don't stop at the first failure: collect them all, then fix or report. Never skip or disable a check to make it pass (AGENTS.md).

## 1. Repository state

```bash
git status --short
git branch --show-current          # must NOT be main: work happens on a branch + PR
git log --oneline origin/main..HEAD
```

## 2. Backend

```bash
cd backend
uv sync --locked
uv run ruff check . && uv run ruff format --check .
uv run pytest -q                                   # unit + API
docker compose up -d db --wait                     # from repo root, if not running
TEST_DATABASE_URL=postgresql+psycopg://benchtrack:benchtrack@127.0.0.1:5433/benchtrack_test \
  uv run pytest -m integration -q                  # must be N passed, 0 skipped
```

## 3. Frontend

```bash
cd frontend
npm ci && npm run lint && npm test && npm run typecheck && npm run build
```

## 4. Contract and agent tooling

```bash
npx --yes @redocly/cli@2.66.0 lint openapi.yaml
python -m unittest discover -s agent-hooks/tests            # guard + ruff hook
(cd mcp-server && uv run --frozen pytest -q && uv run ruff check .)
python plugins/sync_plugin.py --check                       # plugin copy matches sources
claude plugin validate plugins/benchtrack-dev               # if the claude CLI is available
```

## 5. Security scans

```bash
docker run --rm -v "$PWD:/src" -w /src semgrep/semgrep:1.182.0 semgrep scan --config auto --error
```

When dependencies or the Dockerfile changed, also run pip-audit, npm audit, gitleaks and Trivy, as described in `security/scan-findings.md`, and triage anything new there.

## 6. Image, health and version

```bash
APP_VERSION=$(git rev-parse HEAD) APP_PORT=${APP_PORT:-8000} docker compose up --build -d --wait
curl -s http://127.0.0.1:${APP_PORT:-8000}/api/health     # status ok, database ok
```

The `version` field must equal `git rev-parse HEAD`. Also check that `/` and `/track/BT-DEM22` return the SPA HTML, `/api/nope` returns the JSON 404, and `docker compose logs app --since 5m` shows JSON lines with masked tracking codes.

## 7. PR checklist (paste into the PR description, ticked)

- [ ] Change matches `product-spec.md` §9; conflicts flagged, not silently resolved
- [ ] `openapi.yaml` updated first; Redocly clean; contract parity test passes
- [ ] Tests added for every behaviour change; all suites green (list counts)
- [ ] No secrets, tokens, `.env` contents or real customer data in code, logs, fixtures or screenshots
- [ ] Public routes still expose no PII, notes or cost
- [ ] Migrations (if any) are generated by Alembic, reviewed, and backward compatible for one release
- [ ] Semgrep clean; new dependencies justified, from official registries, audited
- [ ] Image builds; `/api/health` is ok and reports this commit
- [ ] `docs/ai-workflow.md` row added; README/AGENTS/testing docs updated if commands or counts changed
- [ ] Branch pushed, PR opened; **a human reviews and merges** (main is protected)
